AI research / side project

VigilX

An AI-assisted security audit harness.

I’m building the control layer around the models: code mapping, scoped context, model routing, verification, and persistent investigation records. A model’s output is a candidate finding; a human reviews it before reporting.

Read the research ↗

Inside the harness

Start with scope.

Map dependencies and call paths, define the threat model, and choose the code each investigation needs.

Give the model useful context.

Route focused investigations to models. Keep candidate findings separate from verified evidence.

Challenge the finding.

Check the actual code, intervening controls, and claimed impact. Review the evidence before a report goes out.

Keep the investigation record.

Retain evidence, failure causes, and unfinished work so investigations can be re-examined after execution failures.

Application security / provider investigation

At GovTech Edu, I spent months investigating a WAF bypass with the team. Requests reached our applications, but the logged details didn’t explain why. We built a reproducible report; Google confirmed the root cause affecting Classic Application Load Balancers and released a global patch.
